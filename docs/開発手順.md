## 1. セットアップ（初回のみ）

### 1-1. 用意するもの

| 種別 | 内容 | 備考 |
|---|---|---|
| ツール | Git / Node.js 20 以上 / Python 3.10 以上 | 開発機は Node 25・Python 3.12 で動作確認済み |
| ツール | GitHub CLI（`gh`） | 任意。PR をターミナルから作る場合 |
| ツール | VS Code + ESLint / Prettier / Python 拡張 | `.vscode/extensions.json` に推奨拡張あり。保存時に ESLint fix が走る設定済み |
| 権限 | GitHub `0122POND/optical-device-ui` への write | 管理者（0122POND）に招待を依頼 |
| ファイル | 学習済みモデル `backend/models/best_model_resnet50.pth` | AI 推論を触る人だけ。git 管理外、担当者から受領（約 590MB） |
| ファイル | 計測データ（`data/row_data/` の BMP 群、Keyence CSV など） | git 管理外。担当者から受領 |
| GPU（任意） | CUDA 対応 GPU + CuPy | GPU 前処理を試す人だけ。Mac では不要（前処理は CPU、AI 推論は MPS が自動で使われる） |

### 1-2. clone と依存関係

```bash
git clone https://github.com/0122POND/optical-device-ui.git
cd optical-device-ui

npm install                              # ルート: husky + lint-staged（pre-commit フック）
cd frontend && npm install && cd ..      # フロントエンド
pip3 install -r backend/requirements.txt # バックエンド（torch 等を含むので時間がかかる）
```

- ルートの `npm install` を忘れると pre-commit フックが入らず、CI で Prettier に落ちる
- `backend/requirements.txt` のコメントは **英語のまま**にする（Windows の cp932 でインストールが失敗した実績あり）
- GPU 前処理を使う場合のみ `pip install cupy-cuda11x`（または `cupy-cuda12x`）。CuPy が無い状態で UI の GPU モードを選ぶと失敗する（既定は CPU）

### 1-3. データとモデルの配置

```
optical-device-ui/
├── backend/models/best_model_resnet50.pth   # AI 推論用（UI で選べる唯一のモデル）
└── data/
    ├── row_data/      # 入力画像 img_001.bmp ...（前処理・AI 推論の入力）
    ├── result/        # 前処理結果（自動生成）
    ├── mask_result/   # AI 推論結果（自動生成）
    └── surface_keyence/   # Keyence 正解 CSV（評価ツールで使う）
```

- `data/` は丸ごと `.gitignore`。ルート直下の `*.csv` `*.png` `*.bmp` や解析フォルダ（`WI5000/` `out/` 等）も除外済みなので、計測データをリポジトリ直下に置いても `git status` は汚れない
- モデルは学習リポジトリ `line-finder-ai` の `model/<arch>/best_model.pth` を、`backend/ai_inference.py` の `MODEL_CONFIGS` にある `checkpoint` 名へリネームして置く

### 1-4. 起動と動作確認

```bash
./start_mac.sh          # macOS / Linux。Windows は start_win.bat をダブルクリック
```

スクリプトは 8000 / 5173 番の残存プロセスを kill → uvicorn（バックグラウンド）→ Vite の順に起動し、ブラウザを自動で開く。停止は Ctrl+C か `./stop_mac.sh` / `stop_win.bat`、または UI の終了ボタン。

手動で起動する場合（バックエンドのログを分けて見たいとき）:

```bash
# ターミナル1
cd backend && python3 -m uvicorn app:app --host 0.0.0.0 --port 8000 --reload
# ターミナル2
cd frontend && npm run dev
```

- **`python app.py` では起動しない**（`__main__` が無い）。`uvicorn app:app` を使う
- <http://localhost:5173> を開き、CPU モード・「硬貨」で START → 3D 点群が出れば OK。`curl localhost:8000/health` が `{"ok":true}` を返すことも確認
- `/data` へのリクエストは `vite.config.ts` のプロキシで 8000 番へ流れる。WebSocket は `ws://<hostname>:8000/ws` に直接繋ぐ

## 2. 開発サイクル

全体像:

```
main を最新化してブランチを切る（feature/... / fix/...）
  → 実装・ローカルで確認
  → format / lint / build
  → コミット（[add] [fix] [change] ... 説明は日本語）
  → PR 作成 → CI → レビュー → main へマージ
  → 計測PC・展示PC へ反映（デプロイ手順.md §4）
  → ブランチ削除
```

### 2-1. ブランチを切る

```bash
git switch main && git pull
git switch -c feature/auto-rotate-wake-lock
```

- 形式は `<type>/<英語スラッグ>`。type は `feature` / `fix` / `refactor` / `chore` / `docs`
- 必ず main から切る。**main への直接 push はしない**（GitHub 側のブランチ保護は未設定なので、運用ルールとして守る）
- 1 ブランチに複数機能を積み上げると PR が肥大化する（過去に 1 PR で数十コミットになった例あり）。機能ごとに切り直す

### 2-2. 実装する

どこを触るかの早見表:

| 変更したいもの | 場所 | ローカルへの反映 |
|---|---|---|
| 画面全体・状態・モード切替（3D/2D、断層、寸法測定） | `frontend/src/App.tsx`（約 2200 行、まだ大きい） | 保存で即（HMR） |
| ヘッダー / 設定タブ / 測定結果タブ | `frontend/src/components/{Header,SettingsTab,ResultTab}.tsx` | 同上 |
| 3D 描画（Plotly の差分更新・寸法線ドラッグ） | `frontend/src/hooks/usePlotly.ts` | 同上。**挙動が変わらないときはページ完全リロード**（HMR が古い描画ループを掴むことがある） |
| 点群の three.js 描画・自動回転 | `frontend/src/components/ThreePointCloudView.tsx` / `hooks/usePlotlyAutoRotate.ts` / `hooks/useWakeLock.ts` | 同上 |
| 断層グラフ | `frontend/src/hooks/useSlicePlot.ts` | 同上 |
| WebSocket 通信・進捗 | `frontend/src/hooks/useWebSocket.ts` | 同上 |
| CSV 入出力・点群構築・色レンジ | `frontend/src/utils/{csv,pointCloud,colorRange}.ts` | 同上 |
| 定数・共有スタイル | `frontend/src/utils/{constants,styles}.ts` | 同上 |
| API・WebSocket コマンド | `backend/app.py` | `--reload` 付きなら自動、起動スクリプト経由なら再起動 |
| 前処理アルゴリズム | `backend/preprocessing_*.py`（`app.py` の `algorithm` 分岐で動的 import） | 同上 |
| AI 推論・モデル追加 | `backend/ai_inference.py` の `MODEL_CONFIGS` + `App.tsx` の `<option>` | 同上 |
| 解析・評価スクリプト | `tools/*.py`（アプリからは呼ばれない独立 CLI） | 直接実行 |

フロントエンドの制約（ESLint で強制される）:

- `verbatimModuleSyntax` のため型は `import type` で読む
- `react-hooks/exhaustive-deps` 有効。render 中の ref 書き込みは禁止（effect で同期する）
- `noUnusedLocals` / `noUnusedParameters` 有効。未使用変数はビルドが落ちる

バックエンドの前処理を足すときの約束:

- `run_preprocess(data_path, result_path, progress_callback, ...)` と `save_peak_results(...)` の 2 関数を同じシグネチャで持たせ、`app.py` の 2 箇所の分岐に追加する
- `progress_callback` は WebSocket 切断時に `WorkerCancelled` を投げて処理を止める仕組みになっている。長い処理の途中には必ず呼ぶ
- `preprocessing_coin2_paper_cpu.py` は論文用ベースライン。**除去した処理への言及をファイル内に書かない**方針（特許予定のため）

### 2-3. 確認する

PR を出す前の最低ライン:

```bash
cd frontend
npm run format:check   # Prettier（CI と同じ）
npm run lint           # ESLint
npm run build          # tsc -b + vite build
```

- 3D 描画・断層・寸法測定・CSV 読込に触れたら、ブラウザで **クリック / カメラ保持 / 3D⇔2D 切替 / 寸法線ドラッグ / 断層** を一通り触る。ここは型チェックでは守れない
- 前処理に触れたら、`data/row_data/` の全スタックで 1 回走らせる（サブセットだと背景中央値が変わる）
- Python 側に公式の lint は無い。`black` / `mypy` を推奨するが必須ではない

### 2-4. コミットする

```bash
git add frontend/src/App.tsx          # ファイル単位でステージ
git commit -m "[add] 自動回転中の画面スリープ防止（Screen Wake Lock API）"
```

- プレフィックスは `[add]` `[fix]` `[change]` `[update]` `[remove]` `[refactor]` `[docs]` `[chore]`。説明は日本語
- 1 コミット = 1 つの意味のまとまり。UI とバックエンドを混ぜない
- pre-commit フック（husky + lint-staged）が `frontend/src/**/*.{ts,tsx}` に Prettier と ESLint --fix をかける

> **部分ステージ（`git add -p` のハンク単位）でコミットしない。**
> lint-staged が「未ステージ変更を退避 → 整形 → 復元」する過程で、未ステージのハンクが別の位置に挿入されてコードが壊れた実例がある（style 属性が JSX の子テキストに漏れて画面に文字列が出た。tsc も lint も通ってしまい気づきにくい）。
> どうしても分割したいときは、先に `npm run format` / `lint` / `build` を通してから `git commit --no-verify` でフックを介さずコミットし、コミット後に `git show HEAD:<file>` で該当箇所を目視する。

- `data/`・`.pth`・計測 CSV は `.gitignore` 済みだが、`git diff --cached --stat` で大きなファイルが混ざっていないか最後に見る

### 2-5. PR を出す

```bash
git fetch origin && git rebase origin/main   # main の最新を取り込む（merge でも可）
git push -u origin HEAD
gh pr create --web
```

- タイトルはコミットと同じ形式（`[fix] 縦解像度が低い環境でサイドパネル下部が見切れる問題を修正`）。複数コミットをまとめる PR は内容を要約する
- 本文は `## Summary`（変更点の箇条書き）と `## Test plan`（確認したこと）。ブラウザで確認した操作は具体的に書く
- CI（`.github/workflows/ci.yml`）は Prettier / ESLint / Build の 3 つ。**全部通るまでレビュー依頼しない**
- Dependabot の PR（`[chore]: Bump ...`）は月次で来る。フロントの依存更新は `npm run build` と 3D 表示の目視確認をしてからマージする。放置分が溜まっているので、まとめて処理するときは 1 つずつ

### 2-6. レビューとマージ

1. CI が通ったら、`docs/` `CLAUDE.md` 程度の軽微な変更は作者がそのままマージしてよい（これまでの PR は作者マージで運用してきた）
2. 前処理アルゴリズム・AI 推論・3D 描画の中核（`usePlotly.ts` / `App.tsx` の描画まわり）に触れる PR は、他メンバー 1 名にレビューを依頼してからマージする。GitHub のブランチ保護は未設定なので運用ルールとして守る
3. 修正を push したら再度レビューを依頼する
4. マージ後、リモートブランチは削除する。ローカルも `git switch main && git pull && git branch -d <branch>`

### 2-7. マージ後の作業

- 計測PC・展示PC に反映が必要なら `docs/デプロイ手順.md` §4（pull）と §6（起動後チェック）を実施する。誰がやるかは PR で決めておく
- `backend/requirements.txt` や `frontend/package.json` を変えた PR は、配備先での `pip install` / `npm install` が必要になる。PR 本文に明記する
- `.pth` の追加・差し替えは git に乗らないので、**配備先への手動コピーを別途行う**
- `docs/API.md` `docs/ARCHITECTURE.md` `CLAUDE.md` に影響する変更は同じ PR で更新する（CLAUDE.md は `.gitignore` に入っているが追跡済みなので、`git add -f` 不要で通常どおりコミットできる）

## 3. 解析ツール（tools/）の開発

`tools/` はアプリ本体から独立した CLI スクリプト群（補間・外れ値除去・スティッチング・Keyence 基準の定量評価など）。使い方と得られた知見は `CLAUDE.md` にまとめてあるので、新しいツールを足したら CLAUDE.md にも節を追加する。

- 入出力は Keyence 互換 CSV（`-9999.9` = 欠損）に揃える
- 図は matplotlib の Agg バックエンドで `out/` に出す。日本語ラベルは macOS の Hiragino を前提にしているので Windows で使う人はフォント候補を追加する
- 評価の作法（`--mode fixed` を主評価にする、共通有効領域で比較する、RMSE の二乗差から追加誤差を求めない、AI マスクを真値にしない）は `CLAUDE.md` の `compare_to_reference.py` の節に従う

## 4. 困ったとき

| 症状 | 見るところ |
|---|---|
| コミット時に Prettier / ESLint で止まる | フックが正常に動いている。指摘どおり直すか `npm run format` を実行 |
| コミット後にコードが壊れている（画面に謎の文字列など） | 部分ステージ + lint-staged の既知問題（§2-4）。`git show HEAD:<file>` で確認して修正コミット |
| CI の Prettier だけ落ちる | ルートで `npm install` していない（フックが入っていない）。`cd frontend && npm run format` |
| `npm run build` が未使用変数で落ちる | `noUnusedLocals` / `noUnusedParameters`。使わない引数は `_` 始まりにする |
| GPU モードで即失敗 | CuPy 未導入。Mac では CPU モードを使う |
| AI 推論がモデルロードで失敗 | `backend/models/best_model_resnet50.pth` が無い（§1-3） |
| ブラウザは開くが「接続中」のまま | uvicorn が起動していない。8000 番の衝突か import エラー。バックエンドのログを見る |
| 3D の挙動が変えたはずなのに変わらない | HMR が three.js / Plotly の古い描画ループを掴んでいる。ページを完全リロード |
| 前回プロセスが残っていて起動できない | `./stop_mac.sh` / `stop_win.bat` を先に実行 |
| `git status` に大量の計測ファイルが出る | `.gitignore` の対象外の場所に置いている。ルート直下か `data/` に移す |

アプリの起動まわりは `README.md`、配備先の問題は `docs/デプロイ手順.md` §9 を先に見る。
